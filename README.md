# ml_deployment_session
ML-сервис для прогнозирования дефолта по кредитным картам с контейнеризацией и A/B-тестированием.

---

## Описание

Цель проекта: разработать и внедрить в production-like-среду сервис машинного обучения для прогнозирования дефолта по кредитным картам, который охватывает полный цикл от сохранения модели до организации A/B-тестирования.

Домен: финансы / кредитный скоринг.

Датасет: [Default of Credit Card Clients Dataset](https://www.kaggle.com/datasets/uciml/default-of-credit-card-clients-dataset/data)

Описание: датасет содержит информацию о клиентах кредитной карты на Тайване с таргетом default.payment.next.month (дефолт в следующем месяце). Включает демографические данные, историю платежей, суммы счетов.

Актуальность: идеально подходит для демонстрации полного цикла внедрения ML-модели в production без излишней сложности в части построения модели.

## Продакшн-окружение (uWSGI + NGINX)
Flask встроенный сервер не предназначен для продакшна.

### Ограничения:
- один поток выполнения
- слабая устойчивость под нагрузкой
- отсутствие балансировки

### Стек:
- **uWSGI** — запуск нескольких воркеров приложения
- **NGINX** — reverse proxy и балансировка

```text
Клиент → NGINX → uWSGI → Flask
```

## Архитектура системы
### Монолит
Текущая реализация — монолитный сервис.

Причины: простота развертывания, низкая задержка, отсутствие межсервисных вызовов, подходит для одной ML-модели.

Когда нужны микросервисы: при наличии нескольких независимых команд, высокой нагрузки или необходимости независимых релизов компонентов.

### Очереди сообщений (RabbitMQ)
- Используется при масштабировании системы.
- Сценарии: асинхронные предсказания, batch-обработка запросов, вынос логирования.
- Схема: клиент отправляет запрос в очередь, ML-сервис обрабатывает его и возвращает результат, при этом логи могут уходить в отдельное хранилище.

```text id="q1"
Клиент → Очередь → ML-сервис → Ответ
                      ↓
                   Логи → Хранилище
```

## Бизнес-метрики
### Ожидаемые потери
EL = Σ (лимит × P(дефолта) × LGD)

Где:
- лимит — кредитный лимит клиента  
- P(дефолта) — предсказание модели  
- LGD — доля потерь при дефолте (например 0.75)

### ROI
ROI = (сэкономленные_потери − стоимость_модели) / стоимость_модели

Где:
- сэкономленные_потери — разница между baseline и моделью  
- стоимость_модели — разработка и инфраструктура  

Положительный ROI означает экономическую целесообразность.

## A/B тестирование
### Цель
Сравнение модели v1 (RandomForest) и v2 (альтернативная модель, например XGBoost) по качеству классификации дефолта.
Гипотеза: v2 улучшает F1-score по классу дефолта без ухудшения Precision.

### Разделение трафика
Сплит 50/50 по пользователю через хеш, чтобы один пользователь всегда попадал в одну группу.

### Метрики
| Метрика | Роль | Причина |
|----------|------|--------|
| F1 (default=1) | основная | баланс Precision и Recall |
| Precision (default=1) | вспомогательная | контроль ложных отказов |

Recall важен, но его рост без Precision приводит к ошибочным отказам и потерям.


### Длительность

- минимум: 14 дней  
- ориентир: ≥ 1000 событий на группу  

При трафике 200/день:
```text id="dur1"
10 дней ≈ (2000 / 200)
```

### Статистика
Используется z-тест для долей.
```text
z = (p_test - p_control) / sqrt(p_pooled(1 - p_pooled)(1/n1 + 1/n2))
```

### 95% доверительный интервал
Δ ± 1.96 × SE

### Решение
| Условие | Действие |
|----------|----------|
| p < 0.05 и ΔF1 > 0.02 | выкатываем v2 |
| p ≥ 0.05 | оставляем v1 |
| p < 0.05 и ΔF1 < 0 | откатываем v2 |
